# ThinkPad(CPU)での gemma4:12b-it-q4_K_M 実測 (2026-10-24)

環境: Ryzen 7 7735HS(8C/16T)、DDR5-4800 16GB×2(実使用可 30.8GB)、内蔵Radeon、Windows版 Ollama **0.30.9**、think=false、temperature 0.3、num_ctx 4096、Brave/ChatGPT/Claude等は起動したまま(測定開始時の空き 13.7GB)。
スクリプト: `eval/measure_local.py`、生データ: `eval/results/local_thinkpad_gemma4.json`。プロンプトは v3(619トークン)＋JSONスキーマ制約。モデルID `6114515d63c1`(Colab/IronClawと同一)。

## 速度
| 呼び出し | wall | prompt評価 | 出力 | decode |
|---|---|---|---|---|
| cold(ロード込み,「原点に戻って」) | 55.2s | 616tok / 35.3s | 74tok | 8.3 tok/s |
| 単純(1ステップ) | 37.9s | 619tok / 30.7s | 60tok | 8.9 tok/s |
| 同一入力の2回目 | **7.9s** | 619tok / **0.7s** | 60tok | 8.9 tok/s |
| 迂回が要る(初回) | 40.6s | 619tok / 30.0s | 88tok | 8.6 tok/s |
| 迂回が要る(再計画) | 32.3s | 822tok / 13.1s | 155tok | 8.3 tok/s |
| 長い複合 | 55.0s | 639tok / 30.9s | 201tok | 8.5 tok/s |
| 曖昧(clarify) | 37.0s | 614tok / 29.7s | 37tok | 5.4 tok/s |

- decode は **約8.6 tok/s**(推定の4〜7より速い)。ロード 11s。
- **支配的なのは prompt評価(約20 tok/s、619トークンで約30秒)**。decode は6〜24秒。
- プロンプトキャッシュは **同一入力のときだけ**効く(0.7s)。システムプロンプトが同じでも指示文が変わると再評価される(Gemma系のスライディングウィンドウ注意のため部分的な前方一致が使えない可能性。要確認)。再計画は直前の会話が前方一致するので 13s に短縮。
- 1回の計画: **約38〜55秒**。再計画が入るとさらに約30秒。
- 計画の中身は妥当(単純→1ステップ、迂回→再計画で wp_north 経由、曖昧→clarify)。

## 判断材料
- LLM単体で **約9.2〜9.8GB**。今の常駐アプリのままだと、残りは約 4.5GB。Docker Desktop(待機1.5〜2.5GB)＋ROS2/Gazebo コンテナ(3〜4GB、推定)を載せるには **1〜2GB不足**。BraveとChatGPTアプリを閉じれば約6〜7GB空く。
- 計画1回が約40秒 → 動画(1〜3分、倍速可・明記)では、LLM待ちの区間を倍速にしても、指示3〜4件でほぼ尺を使い切る。

## 短縮の候補(未実施)
1. システムプロンプトを短くする(619→約250トークンで prompt評価を約12秒に)。ただし v3 の判定規則を削ると精度が変わる → 再評価が要る(新しい評価集合)。
2. Ollama を 0.40系へ更新して Vulkan(iGPU)を試す。0.40.8 は `OLLAMA_VULKAN` が既定で有効。prompt評価(計算律速)が速くなる可能性があるが、効果は未確認で、インストーラのダウンロードが要る(承認制)。
3. 指示ごとに前方一致するよう、システムプロンプトの後ろに指示を置く現構成のまま、**固定の質問文を使う動画構成**にして、同一入力キャッシュ(約8秒)を使う…は「AIを使っている」説明が弱くなるので非推奨。
