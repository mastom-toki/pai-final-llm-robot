# 依頼：ローカルLLMのモデル選定（Ollama・日本語・構造化出力）

## 目的
大学講座の最終課題で、日本語の指示（例:「赤い箱の前まで行って止まって」）を、ロボットの実行計画（JSON）に変換するローカルLLMを選びたい。API（クラウドLLM）は使わない。**2026年10月時点の最新情報**でお願いします（あなたの知識が古い可能性があるので、必ずWeb検索で確認し、出典のURLと公開日を付けてください）。

## 使い方の条件
- ランタイム: **Ollama 0.40.8**（Docker, GPUはNVIDIA RTX 5090 32GB。ただし他の作業と共有するため、**このモデルに使えるVRAMは10〜14GBまで**。コンテキストは4096トークン程度、KVキャッシュ込みでこの範囲に収めたい）。
- 入力: 日本語の短い指示（1〜3文）＋プロンプト内の物体リスト（id・種類・色）＋禁止ルールの説明。
- 出力: JSON。**Ollamaの構造化出力（`format` にJSON Schemaを渡す制約付きデコード）を使う**。スキーマは `anyOf` ＋ `const`（status が ok / clarify / reject の3形、steps は最大8個、action は move_to / rotate_to_face / rotate / wait / stop の5種、target はenum）。
- 求める振る舞い:
  1. 指示を正しいステップ列に分解する（複合指示を含む。例「赤い箱に近づいて3秒待ち、青い円柱を向いて、緑の立方体まで行って原点に戻って」）。
  2. 曖昧な指示（「あれのところに行って」）は clarify、存在しない物体や禁止されたことは reject を返す。
  3. 検証で失敗したとき、理由コード（例 FORBIDDEN_ZONE）と観測結果を渡すと、**迂回する経由点を使った計画に修正できる**（再計画）。
- 性能: 1回の応答は数秒以内が望ましい。思考（reasoning）トークンを大量に出すタイプは、遅延とJSON崩れのリスクが気になる。
- ライセンス: コードは公開リポジトリに載せる（モデル自体は再配布しない）。課題用途（非商用）で使えること。ライセンス上の注意があれば教えてください。

## 知りたいこと
1. **候補を3つ**、優先順位付きで。各候補について:
   - Ollamaでの正確なタグ（例 `名前:サイズ-量子化`）と、そのタグがOllamaライブラリに実在するか（検索で確認）。
   - 量子化（Q4_K_M など）ごとのVRAM目安（コンテキスト4096時）。10〜14GBに収まる構成を明記。
   - 日本語の指示理解の質（日本語ベンチマークや報告があれば）。
   - 構造化出力・関数呼び出し（JSON Schema遵守）に関する評価や既知の問題。Ollamaの制約付きデコードとの相性（特に `anyOf` / `const` / enum）。
   - 速度の目安（RTX 5090クラスでの tokens/sec の報告があれば）。
   - ライセンス。
2. 3候補を比べた**推奨と、その理由**（「なぜ1位か」「どんなときに2位・3位に切り替えるか」）。
3. 「このタスクではサイズを上げるより、プロンプトとスキーマの設計を先に詰めるべきか」という意見。
4. 5〜10分で試せる**比較の手順**（Ollamaのコマンドと、20件程度の指示でスキーマ適合率・正答率を測る方法の提案）。

## 回答の形式
- 先頭に結論（推奨1つ）を3行で。
- 候補は表にする（タグ / VRAM / 日本語 / 構造化出力 / 速度 / ライセンス / 出典）。
- 確認できなかった項目は「未確認」と書き、推測で埋めない。
